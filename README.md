# B站网页版音质选择

在 B 站网页播放器的控制栏里直接选音频档位。

B 站网页版没有独立的音质选项。这个脚本在播放器读到取流响应之前，把 `dash.audio` 过滤成只剩你选的那一档——播放器只能用它。

## 功能

- 控制栏里多出一个音质按钮，挨着清晰度，显示**当前实际在用的档位**（选「自动」时，如果播放器自己挑的是 64K，就显示 64K）
- 点开可选：自动 / 最高可用 / 64K / 132K / 192K / 杜比全景声 / Hi-Res 无损（后两个取决于片源和账号权限）
- 当前浏览器播不了的编码（例如 Linux 下的杜比 ec-3）会置灰
- 选择会记住，下次打开直接生效
- 换档后自动从原来的播放位置继续

## 安装

需要先装 [Tampermonkey](https://www.tampermonkey.net/) 或 [Violentmonkey](https://violentmonkey.github.io/)。

**直接安装（推荐）**

点下面的链接，脚本管理器会弹出安装页：

[B站音质选择.user.js](https://raw.githubusercontent.com/stevenamt/bilibili_yinzhixuanzejiaoben/main/B%E7%AB%99%E9%9F%B3%E8%B4%A8%E9%80%89%E6%8B%A9.user.js)

**手动安装**

1. 打开脚本管理器，新建脚本
2. 把 `B站音质选择.user.js` 的内容贴进去，保存
3. 打开任意视频页

> 脚本头里的 `@run-at document-start` 别改。必须在首屏取流之前注入，否则拦不到，按钮也不会出现。

## 更新

脚本头里带了 `@updateURL` / `@downloadURL`，装好之后由脚本管理器负责升级：

- Tampermonkey / Violentmonkey 默认每 24 小时检查一次，也可以在管理面板里点「检查更新」立即拉取
- 只有 `@version` 变大才会覆盖，改了代码忘改版本号是不会更新的
- 从 Greasy Fork 安装的话，更新走 Greasy Fork 的地址，由它托管

仓库地址变了（改仓库名、换分支）要同步改脚本头里的 `@namespace` / `@updateURL` / `@downloadURL`，否则更新会指向旧地址。

## 使用

控制栏右侧、清晰度右边会出现「64K」「132K」「192K」「杜比」「无损」这样的按钮，显示当前实际在用的档位。点开选一档，页面会重载并接着原来的位置播放。

- 鼠标：点按钮 → 选一档
- 键盘：`Tab` 聚焦按钮 → `Enter` 或空格打开 → `↑` `↓` 选择 → `Enter` 确认，`Esc` 关闭

## 说明

- **档位名 ≠ 实际码率。** 64K / 132K / 192K 是平台给这一档设的目标码率，实际码率取决于投稿源。普通投稿的 192K 档实测常常只有 160 多 kbps，132K 和 192K 也经常听不出差别。菜单里显示的是接口返回的实测值，所以会出现「132K 档显示 90 kbps」这种情况。
- 换档会重载一次页面：取流在切换前就已经发生，不重载不生效。
- 杜比全景声 / Hi-Res 无损取决于片源是否带对应音轨，以及当前账号是否有权限。没有就不会出现在菜单里，脚本不会凭空造出音轨。
- 档位列表在页面加载时确定，之后需要刷新才能更新。

## 已知限制

- 只处理网页播放器（`www.bilibili.com` 的视频、番剧、列表、活动页），不涉及 App 和小程序
- 直播不适用
- B 站改播放器结构后按钮可能不再出现，需要按新的控制栏选择器调整
- 播放进度恢复是尽力而为：从重载前的 `currentTime` 接续，个别页面可能被站内自己的进度记忆覆盖

## 工作原理

`x/player/playurl` 的响应里，`data.dash.audio` 同时带 64K / 132K / 192K 多路音频，选哪一路由播放器决定，服务端没有「指定音质」的参数。脚本在播放器读到响应之前把 `dash.audio` 过滤成只剩目标那一路，三条路径都拦：

1. 首屏内联的 `window.__playinfo__`（用 getter/setter 拦截赋值）
2. `window.fetch`
3. `XMLHttpRequest`（在 `send` 之前注册 `readystatechange`，确保早于播放器读取）

过滤后把 `dash.dolby` / `dash.flac` 一并置空，避免播放器继续解析其他音轨。
